# Completed — 2026-11-26: retrieval fixes and hosted folder sync

Branch `fix/retrieval-indexing` (commits `17b20a9`, `142f131`, `6c7198f`; not merged or deployed). Memory ids now come from the owner plus the content hash. Identical text is stored, queued and indexed once. The index handler no longer marks a memory as indexed without writing a vector for it. Accepting a proposal no longer calls the embedder, so Ollama being down can't block it. Keyword search applies the project, kind and validity scope before its limit, so matches from other projects can't crowd out the ones asked for. The negation check that widens a memory's text window now matches whole words near the span only ("know" no longer counts as "no"). Task evidence now includes memories that have no project. A transcript correction marks the old version's memories as superseded, and an unchanged one is revived at the new version. Retrieval trusts the state store over the index and drops non-current memories unless history is requested. Search filters by kind inside the index and reports `index_stale` honestly. ADR 0006 left room for a separate authenticated upload connector, and this adds one for the shared server. The desktop app lists a folder the user picked in the native dialog and sends that list to `POST /v1/connectors/{id}/manifest`. The server re-applies the secret and default excludes, tombstones files that are gone, and asks only for new or changed files. The app uploads those to `PUT /v1/connectors/{id}/files`. The server stores them under the owner's prefix, ingests them from there, and deletes them when the source is purged. It still never reads a client path. Checks: all Python tests, `make check`, 144 web tests, and 66 Rust tests plus clippy pass. Still open: no live run against Ollama (it isn't installed on this machine, and the server copy needs a deploy from `main`); duplicate memories created before this fix stay unindexed; hosted folders sync only on add and "Sync now" in the desktop app (no timer, and none from the browser).
